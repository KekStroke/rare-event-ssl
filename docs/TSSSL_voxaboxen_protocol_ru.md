# Сравнение с Voxaboxen после полевого FT: отличия методов и фиксированный протокол (черновик, запуск только после согласования)

## 1. Чем наш детектор отличается от Voxaboxen

| | Voxaboxen (DCASE 2025, запуск в CETACEANS, май 2026) | Наш детектор (H21, режимы R2/R3) |
|---|---|---|
| Энкодер | BEATs iter3+ AS2M (≈90 M параметров, предобучен на AudioSet), дообучается целиком | компактный modern-блок 8 слоёв d=384 (17.8 M), предобучен нами на синтетике из тех же 45 429 лаб-клипов |
| Предобучение энкодера на целевых данных | нет: BEATs берётся как есть, обучение детектора сразу на синтетике | да: 20k шагов на 5-с смесях; R2 единицы km(AVES) + событийная ветка, R3 только ветка |
| Что предсказывается | на каждом кадре: вероятность начала (anchor), регрессия длительности, класс; двунаправленно (fwd + bck), затем NMS/слияние с IoU 0.5 | наличие, вероятность onset, лог-длительность на 20-мс токенах; класс по сумме покадровых вероятностей; одно направление |
| Декодер | пики + soft-NMS внутри направления, затем fwd/bck объединяются максимальным двудольным паросочетанием (IoU ≥ 0.5), несопоставленные боксы остаются при Detection Prob > comb_discard (подбирается на val) | пики onset (th_on, d_min) + exp(logdur); перекрытия разрешены, NMS нет; пороги под бюджет FA/ч на dev |
| Обучающие данные детектора | 40 синтетических записей × 60 с (min_gap 0.5 с: вызовы не перекрываются), 50 эпох с early stopping | 1–4 вызова на 5 с с кроссфейдом, 37 % вызовов перекрываются; FT 1.5k шагов на полевых метках тренировочных фолдов |
| Полевые метки | не использовались (test = 17 записей Ольги) | используются на FT (train-фолды), dev для порогов |
| Длительность | ограничений нет | обрезка [0.15, 5] с |

Кандидаты на вклад, которые сравнение должно подтвердить или снять: (а) предобучение компактного энкодера на синтетике с событийной веткой вместо большого AudioSet-энкодера; (б) синтетика с перекрытиями и декодер без NMS, допускающий перекрывающиеся экземпляры; (в) рабочая точка под бюджет FA/ч, а не порог 0.5. Пункт (а) проверяется только при равном доступе к полевым меткам, отсюда протокол ниже.

## 2. Фиксированный протокол

1. **Данные.** Те же 17 записей, те же три фолда (FOLDS из common.py), тот же dev: первая запись каждого из двух других фолдов. Для каждого тестового фолда Voxaboxen дообучается на полевых записях остальных двух фолдов за вычетом dev-записей, dev служит для early stopping и выбора порога. Итого три модели Voxaboxen.
2. **Стартовая точка.** final-model.pt из проекта whale_aves (BEATs, обучен на синтетике), параметр previous_checkpoint_fp. Это зеркало нашего «предобучение на синтетике → FT на поле».
3. **Бюджет FT.** Тренировочные записи на фолд это 9–10 файлов, 0.6–0.9 ч аудио (48 кГц моно, Voxaboxen ресемплирует в 16 кГц сам). Наш FT проходит 1.5k шагов × 8 × 10 с ≈ 33 ч аудио, то есть 36–55 эпох по тренировочным записям фолда. Для Voxaboxen берём n_epochs 50 с early stopping по val (patience 10, min_epochs 5, как в исходном запуске), lr 5e-5; другие гиперпараметры не трогаем. Манифесты фолдов готовы: ~/tsssl/vox_field/fold{k}_{train,val,test}_info.csv.
4. **Декодер.** Штатный декодер Voxaboxen (fwd+bck, soft-NMS, объединение по IoU) из его inference, а не моё приближённое слияние сохранённых боксов. Порог детекции сканируется от 0.05 (нужно снять предфильтр 0.5 при инференсе), иначе кривая ниже FAR 60 недоступна.
5. **Метрика.** Наш скорер: class-agnostic strict recall (tau 0.5, offset max(tau, 0.5·dur)), FAR по тесту, рабочая точка под dev-бюджет 100 FA/ч, FAR-согласованные точки 61/100/150, подмножество перекрывающихся референсов, покрытие ≥50 %. Парный бутстрэп по записям против R2 и R3 (по три сида, у Voxaboxen один сид на фолд в первом проходе).
6. **Отчётность.** Сравнение считается решённым только при интервале разности, не содержащем ноль, при FAR 100; иначе фиксируется «не разрешено» с интервалом.

## 2а. Проверено до запуска (2026-10-19 вечер)
- **Чекпоинт детектора есть.** project/whale_aves/final-model.pt (361 МБ, 254 тензора) содержит энкодер BEATs и обе головы: detection_head и rev_detection_head. Старт полевого FT с обученного на синтетике детектора возможен (previous_checkpoint_fp). model.pt (1.4 ГБ) рядом, вероятно с состоянием оптимизатора.
- **Синтетика нашего локального запуска Voxaboxen без перекрытий подтверждена кодом и данными** (относится к run_voxaboxen.py, апрель 2026; опубликованный Voxaboxen обучался и на синтетике с перекрытиями). run_voxaboxen.py размещает клипы последовательно: cursor += clip_dur + uniform(min_gap 0.5, max_gap 3.0). В 40 тренировочных селекционных таблицах 461 событие, перекрывающихся 0. Для сравнения в нашей синтетике по той же событийной мере перекрываются 57 % вызовов (ранее названные 37 % считались иначе).
- **Декодер проверен по коду.** Среда восстановлена: voxaboxen 0.2.0, коммит 20cf966 (github earthspecies/voxaboxen), torch 2.14 cu130. Набор гиперпараметров апрельского params.yaml совпадает с аргументами этой версии один в один, то есть апрельский запуск делался той же версией кода. Штатный декодер: внутри каждого направления пики детекции (peak_distance 5) и soft-NMS (sigma 0.5, порог IoU 0.5); затем объединение fwd и bck через максимальное двудольное паросочетание (Хопкрофт–Карп) по рёбрам с IoU ≥ comb_iou 0.5; сопоставленные пары дают объединённые боксы, несопоставленные боксы обоих направлений сохраняются, если их Detection Prob выше comb_discard_thresh, который подбирается на val (в апреле 0.75). Моё прежнее описание «NMS» было неточным: NMS есть только внутри направления, объединение это паросочетание на графе. Для нашего сравнения инференс запускается штатным кодом с detection_threshold 0.05 и comb_discard, выбранным на val при обучении; кривая recall–FAR строится по Detection Prob объединённых боксов.

## 2б. Запуск (2026-10-19 ~22:40)
После подтверждения трёх пунктов запущен run_vox_field.sh: три фолда, старт с final-model.pt, апрельские гиперпараметры (batch 16, клип 10/5 с, lr 5e-5, энкодер размораживается с эпохи 3, early stopping по val с patience 10, min 5, max 50 эпох), затем штатный инференс на тестовых и dev-записях с detection_threshold 0.05. Логи ~/tsssl/logs/vox_ft_fold*.log.

## 2в. Исправления в коде инференса Voxaboxen 0.2.0 (локальная копия, задокументировано)
Штатная команда inference в этом коммите падает на объединении fwd/bck. Исправлено четыре несоответствия в voxaboxen/inference/inference.py (оригинал сохранён как inference.py.orig): имя атрибута порога (comb_discard_thresh → comb_discard_threshold), имя аргумента (comb_iou_threshold → comb_iou_thresh), папка чтения fwd/bck (experiment_output_dir → папка inference, куда они записаны) и имя файла экспорта (добавлен суффикс -detthresh, который ожидает функция объединения). Алгоритм декодера не менялся. Smoke-тест на одной полевой записи с апрельским чекпоинтом: 203 fwd-бокса при пороге 0.05 (в апреле при 0.5 их было 46), объединение и файл comb создаются.
Для кривой recall–FAR инференс выполняется с comb_discard 0.0, а порог по Detection Prob объединённых боксов сканируется нами: фильтр discard это последний шаг штатного декодера, поэтому порог t на файле с discard 0 в точности воспроизводит штатный декодер с comb_discard = t. Рабочая точка выбирается на dev под бюджет FA/ч так же, как для наших моделей.
Также: project-setup перезаписывает манифесты с индексной колонкой; манифесты для инференса пересобраны (fn, audio_fp).

## 3. Что нужно для запуска
- Среда animal_spot_env, где стоял voxaboxen, удалена; пакет не найден ни в одном venv. Нужна свежая установка (github earthspecies/voxaboxen) в отдельное окружение, веса BEATs на месте (CETACEANS/voxaboxen_weights). Оценка: 30–60 мин установки, три FT по 20–40 мин на 5090, инференс и скоринг 20 мин.
- Полевые аннотации в формате Raven уже есть (OLGA/true_annotations_2026); нужны три train/val/test-манифеста по фолдам.
- Риск: Voxaboxen обучался без перекрытий; при полевом FT с перекрывающимися метками его поведение на подмножестве перекрытий может измениться в любую сторону, это и есть предмет сравнения.
